02. CONFIGURATION BOARD

Briefed incorporates a flexible, layered configuration structure designed to adapt easily to multi-developer teams. Configurations are loaded and deep-merged based on a strict priority cascade:

  1. Local Project Config (.briefed.json) — Repository-specific overrides (committed or ignored).
  2. Global User Config (~/.briefed.json) — System developer credentials (like private keys).
  3. Built-in defaults — System fallbacks.

📋 Complete Blueprint Code

Here is a complete configuration template detailing every operational parameter for .briefed.json:

{
  "target": "auto",
  "backend": "gemini",
  "model": "gemini-2.5-flash",
  "apiUrl": "http://localhost:11434",
  "window": {
    "days": 0,
    "entries": 10,
    "maxTotalWords": 1000
  },
  "ignored": [
    "*.lock",
    "package-lock.json",
    "pnpm-lock.yaml",
    "dist/",
    "coverage/"
  ],
  "minDiffLines": 10,
  "maxSummaryWords": 250
}

⚙️ Configuration Parameter Guide

1. target (Type: string | Default: "auto")

Where entries are written. "auto" means .briefed/context.md: the .briefed/ folder carries its own .gitignore, so the file never dirties your working tree or causes merge conflicts. briefed init links it from CLAUDE.md, AGENTS.md and .github/copilot-instructions.md (creating a starter CLAUDE.md if none exist). Set a path such as "CLAUDE.md" to write entries straight into a committed file, as the CI workflow does. Paths must stay inside the repository.

2. backend (Type: "gemini" | "anthropic" | "ollama" | "none" | Default: auto)

When you don't set it, Briefed picks one from your environment:

  • GEMINI_API_KEY set → "gemini"
  • ANTHROPIC_API_KEY or BRIEFED_API_KEY set → "anthropic"
  • no key → "none": summaries are built from commit messages (and PR titles from merge commits). Free, offline, and the fallback whenever an LLM call fails.
"ollama" runs a local model and must be chosen explicitly.

3. model (Type: string | Default: per backend)

gemini-2.5-flash, claude-haiku-5-5 or llama3, matching the backend. If you override the backend at runtime (briefed run --backend gemini) and the configured model belongs to another backend, Briefed switches to that backend's default and warns.

4. window (Type: object)

Keeps the context file bounded:

  • window.entries (Default: 10): keeps the latest N entries.
  • window.maxTotalWords (Default: 1000): word budget across all entries; the oldest are pruned first.
  • window.days (Default: 0 = off): optional maximum age. Off by default so a quiet week doesn't empty the context.

5. ignored (Type: string[] | Default: ["*.lock", "package-lock.json", "pnpm-lock.yaml", "dist/", "*.map", "*.min.js", "*.min.css"])

.gitignore-style patterns, passed to git as exclude pathspecs, so matching files never reach the summarizer. *.lock and dist/ match at any depth; patterns containing / are anchored at the repository root.

6. minDiffLines (Type: number | Default: 10)

Changes this small (in 2 files or fewer) skip the LLM and use the commit-message summary.

7. maxSummaryWords (Type: number | Default: 250)

Word cap per LLM summary, cut at the last complete line.

🛡️ Automated Secret Scrubbing

Before a diff is sent to any backend (Gemini, Anthropic, or Ollama, since apiUrl can point at a remote host), Briefed masks API keys, database passwords, AWS credentials, bearer tokens, GitHub and npm tokens, and private keys. Gemini never reads ANTHROPIC_API_KEY, so a key is never sent to the wrong provider.

🤖 Core LLM Summarization Prompt

Every backend gets the same prompt, written for the AI agent that will read the result:

You write the "recent changes" note that an AI coding agent reads before working in this repository.
From the commits and diff below, list only facts that change how the agent should work: new, renamed or removed commands, scripts, modules, public APIs, config keys, environment variables, dependencies, conventions, and breaking behavior changes.
Output 1 to 5 lines, each starting with "- ". No headings, no file lists, no line counts, no markdown fences, no filler.
If nothing matters to an agent, output exactly: - Minor changes only.

Commits:
<commit subjects and PR titles, newest first>

Changed files:
<one per line, ignored patterns excluded>

Git diff:
<scrubbed diff; over 8,000 characters each file gets an equal share>

🔌 How agents find the context

briefed init appends this to each agent file it finds. Claude Code resolves the @ import automatically; other agents follow the sentence:

## Recent upstream changes
Before starting work, read .briefed/context.md: what changed upstream recently, newest first (auto-generated by Briefed from git history).
@.briefed/context.md

For agents that support session-start hooks, briefed context prints the same entries to stdout.
