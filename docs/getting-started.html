01. GETTING STARTED GUIDE

Briefed keeps your AI coding agent (Claude Code, Codex, Copilot, Cursor) in sync with what your teammates changed. After every pull, merge, rebase or branch switch, it writes a short note of agent-relevant changes to .briefed/context.md, which your agent files link to. No API key is needed to start.

📦 1. Installation

No install needed: npx briefed-cli init works on its own. To install once for all repos:

npm install -g briefed-cli

⚙️ 2. Hooks Initialization

From the root of any Git repository you want to track:

cd /path/to/your-repo
briefed init            # or: npx briefed-cli init
git add CLAUDE.md && git commit -m "Link Briefed context"

init installs the post-merge, post-rewrite and post-checkout hooks into .git/hooks/ (or .husky/ if present), and appends a link to .briefed/context.md in CLAUDE.md, AGENTS.md and .github/copilot-instructions.md. The .briefed/ folder ignores itself, so the only file to commit is that one-line link. Re-run init after upgrading Briefed to refresh the hooks.

✅ What happens after init

On every git pull, merge, rebase or branch switch, the hook starts Briefed in the background and git returns immediately. Briefed diffs what arrived (lockfiles and build output excluded), summarizes it, and prepends an entry to .briefed/context.md. The last run's output is in .git/briefed.log; briefed status shows when it last ran.

👥 3. Team Setup

Git hooks aren't committed, so each teammate runs npx briefed-cli init once per clone. For npm projects, make it automatic:

{ "scripts": { "prepare": "briefed init" }, "devDependencies": { "briefed-cli": "^0.10.0" } }

The hooks use the project's own node_modules/.bin/briefed before any global install, so everyone runs the pinned version.

🔑 4. Optional: LLM Summaries

Without a key, entries list commit subjects and PR titles. Export a key and Briefed switches to LLM summaries automatically:

# Git Bash / macOS / Linux
export GEMINI_API_KEY="your-key"        # or ANTHROPIC_API_KEY

# Windows PowerShell
$env:GEMINI_API_KEY="your-key"

You can also put "apiKey" in ~/.briefed.json (applies to every repo). Avoid putting keys in a repository's .briefed.json; if you do, gitignore it.

🚀 5. Triggering Your First Sync

briefed run --verbose   # summarize now, with details
briefed status          # last run + latest entry
briefed stats           # local run statistics
💡 CI/CD is optional

Local hooks are the primary mechanism. GitHub Actions only helps if your team merges PRs in the GitHub web UI and wants one committed context file. See the CI/CD Integration guide.

🤖 6. Agents Without Import Support

Claude Code loads .briefed/context.md through the @ import automatically. Codex, Copilot and Cursor read the link's instruction and open the file themselves. For an agent with a session-start hook, run briefed context: it prints the recent changes straight into the agent's context.
